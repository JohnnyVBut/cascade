# Раздельная маршрутизация: российский и зарубежный трафик

Пошаговая инструкция для настройки двух серверов Cascade (Россия + Нидерланды) так, чтобы российские сайты работали через RF выход, а зарубежные — через NL.

## Архитектура

```
[VPN-клиент]
     │
     │  WireGuard (порт 51820)
     ▼
[RF-сервер — Cascade]
     │
     ├─── dst = российские IP ──→ RF интернет (быстро, без блокировок)
     │
     └─── dst = остальные IP ───→ S2S туннель (порт 51821)
                                        │
                                   [NL-сервер — Cascade]
                                        │
                                   NL интернет (обход блокировок)
```

**Что нужно знать заранее:**
- Внешний IP RF-сервера (`curl ifconfig.me` в терминале RF)
- Внешний IP NL-сервера (аналогично)
- Логин/пароль (или API-токен) от Cascade на NL-сервере

> **Вся настройка выполняется из одного браузера** — через вкладку **Remotes** RF-сервер
> берёт управление NL-сервером на себя. Открывать второй браузер не нужно.

---

## Часть 1. Подключить NL-сервер через Remotes

1. Открыть Cascade на **RF-сервере**.

2. В левом меню → **Remotes** → кнопка **+ Add Server**.

3. Заполнить форму:
   - **Name:** `Netherlands` (любое имя)
   - **URL:** `https://[ВНЕШНИЙ_IP_NL]/[СЕКРЕТНЫЙ_ПУТЬ]`

     > Cascade скрыт за случайным путём — на корневом URL показывается сайт-приманка.
     > Секретный путь был показан в конце установки (`setup.sh`) и выглядит примерно так:
     > `https://1.2.3.4/a1b2c3d4ef56/`
     > Если путь утерян — он хранится в конфиге Caddy на NL-сервере:
     > `grep -r "cascade" /etc/caddy/` или `cat /root/cascade/.env`

   - Режим: **Login / Password** или **API Token**
   - Ввести учётные данные от NL-сервера.

4. Нажать **Add** → сервер появится в списке. Нажать **Test** — статус должен стать **✓ OK**.

> После добавления в верхней части сайдбара появится выпадающий список **Server**.
> Переключение между серверами происходит прямо в нём — без смены вкладки браузера.

---

## Часть 2. Настроить RF-сервер

В выпадающем списке **Server** выбрать **🏠 Local** (RF-сервер).

### 2.1. Профиль обфускации AWG (рекомендуется)

> Один профиль используется для **всех** интерфейсов на обоих серверах — клиентского и S2S.
> Если хотите WireGuard 1.0 без обфускации — пропустите раздел 2.1 и используйте Quick Create.

5. **AWG2 Templates** → **+ Add Template**:
   - Name: `awg-profile`
   - Profile: выбрать пресет (например, **QUIC** или **TLS 1.3**)
   - Нажать **Generate** → **Save**.

5а. **Export JSON** рядом с шаблоном `awg-profile` — файл понадобится на NL-сервере (шаг 10).

   > Перед handshake AWG отправляет junk-пакеты, первый из которых (I1) имитирует
   > выбранный протокол. H1-H4, Jc/Jmin/Jmax **должны совпадать** на обоих концах —
   > именно по ним стороны распознают пакеты друг друга. Экспорт/импорт JSON
   > гарантирует совпадение без ручного копирования.


### 2.2. Интерфейс для клиентов

6. **Interfaces** → **+ Add Interface**:

   | Поле | Значение |
   |------|----------|
   | Name | `wg0` |
   | Protocol | `AmneziaWG 2.0` |
   | Listen Port | `543` *(или любой порт < 1024 — реже блокируются DPI)* |
   | Address | `10.0.0.1/24` *(подсеть можно выбрать любую достаточного размера; не использовать нулевой адрес — например `10.0.0.0/24` некорректно, нужно `10.0.0.1/24`)* |

   В секции **AmneziaWG 2.0 Parameters** выбрать шаблон `awg-profile` → **Save** → **Start**.

   > Клиенты должны использовать приложение **AmneziaWG** (не стандартный WireGuard),
   > иначе подключение не установится.

### 2.3. S2S-интерфейс к NL

7. **Interfaces** → **+ Add Interface** → выбрать **Manual**:

   | Поле | Значение |
   |------|----------|
   | Name | `wg-nl` |
   | Protocol | `AmneziaWG 2.0` *(тот же, что выбрали выше)* |
   | Listen Port | `544` *(порт < 1024 реже блокируются DPI; можно выбрать любой свободный)* |
   | Address | `10.100.0.1/30` *(адрес можно выбрать любым; оба конца S2S должны входить в одну подсеть — рекомендуется /30)* |
   | Disable Routes | ✓ включить |

   В секции **AmneziaWG 2.0 Parameters** выбрать шаблон `awg-profile` → **Save** → **Start**.

8. Кликнуть на интерфейс `wg-nl` → **Export Params** → скачается `wg-nl.json`.

### 2.4. NAT на RF-сервере

9. **NAT** → вкладка **Outbound** → **+ Add Rule**:

    | Поле | Значение |
    |------|----------|
    | Source | `10.0.0.0/24` |
    | Interface | `eth0` *(главный сетевой интерфейс)* |
    | Type | MASQUERADE |

    **Save**.

## Часть 3. Настроить NL-сервер

В выпадающем списке **Server** выбрать **🌐 Netherlands**.

> В сайдбаре появится жёлтая метка **⚡ Managing remote server** — все изменения
> теперь применяются на NL-сервере.

### 3.1. Профиль обфускации AWG (только AmneziaWG 2.0)

10. **AWG2 Templates** → **Import JSON** → выбрать файл из шага 5а.

    > Тот же профиль используется на обоих серверах без изменений — H1-H4 и Jc/Jmin/Jmax
    > должны совпадать, и импорт гарантирует это автоматически.

### 3.2. S2S-интерфейс к RF

11. **Interfaces** → **+ Add Interface** → выбрать **Manual**:

    | Поле | Значение |
    |------|----------|
    | Name | `wg-rf` |
    | Protocol | `AmneziaWG 2.0` *(тот же, что на RF-сервере)* |
    | Listen Port | `544` *(порт < 1024; независим от порта в шаге 7 — может быть любым)* |
    | Address | `10.100.0.2/30` *(второй адрес из той же /30 подсети что в шаге 7)* |
    | Disable Routes | ✓ включить |

    В секции **AmneziaWG 2.0 Parameters** выбрать шаблон `awg-profile` → **Save** → **Start**.

12. Кликнуть на интерфейс `wg-rf` → **Import JSON** → выбрать файл `wg-nl.json` из шага 8.

    > Файл содержит адрес, порт, публичный ключ и PSK интерфейса `wg-nl` с RF-сервера.
    > Пир создастся автоматически — Endpoint, Allowed IPs и PSK заполнятся из файла.
    > Ничего вводить вручную не нужно.

13. **Routing** → **Static Routes** → **+ Add Route**:

    | Поле | Значение |
    |------|----------|
    | Destination | `10.0.0.0/24` |
    | Gateway | `10.100.0.1` |
    | Interface | `wg-rf` |

    **Save**.

    > Без этого маршрута NL не знает как доставить ответный трафик обратно к VPN-клиентам:
    > `Disable Routes` на `wg-rf` отключает автоматическое добавление маршрутов WireGuard.

14. Кликнуть на интерфейс `wg-rf` → **Export Params** → скачается `wg-rf.json`.

### 3.3. NAT на NL-сервере

15. **NAT** → **Outbound** → **+ Add Rule**:

    | Поле | Значение |
    |------|----------|
    | Source | `10.0.0.0/24` |
    | Interface | `eth0` |
    | Type | MASQUERADE |

    **Save**.

### 3.4. Разрешить форвардинг трафика

16. **Firewall** → **Rules** → **+ Add Rule**:

    | Поле | Значение |
    |------|----------|
    | Source | `10.0.0.0/24` |
    | Destination | `any` |
    | Action | ACCEPT |

    **Save**.

## Часть 4. Вернуться на RF-сервер и завершить S2S

В выпадающем списке **Server** выбрать **🏠 Local**.

### 4.0. Импортировать параметры NL-сервера

17. Кликнуть на интерфейс `wg-nl` → **Import JSON** → выбрать файл `wg-rf.json` из шага 14.

    > Файл содержит адрес, порт, публичный ключ и PSK интерфейса `wg-rf` с NL-сервера.
    > Пир создастся автоматически — Endpoint, Allowed IPs и PSK заполнятся из файла.
    > Ничего вводить вручную не нужно.

    > ✅ При корректной настройке **Handshake** появится в обоих интерфейсах сразу после создания пира — туннель поднялся.

### 4.1. Проверить туннель через Speed Test *(опционально)*

18. **Remotes** → кнопка **⚡ Speed Test**:
    - **From:** Local (RF)
    - **To:** Netherlands
    - **Via:** S2S Tunnel
    - Нажать **Run** — покажет реальную пропускную способность туннеля.

### 4.2. Шлюз (Gateway)

19. **Gateways** → **+ Add Gateway**:


    | Поле | Значение |
    |------|----------|
    | Name | `netherlands` |
    | Interface | `wg-nl` |
    | IP | `10.100.0.2` |
    | Monitor | ✓ включить |
    | Ping target | `1.1.1.1` |

    **Save**. Подождать ~30 секунд — статус должен стать **Online** (зелёный).

### 4.3. Алиас с российскими IP

20. **Firewall Aliases** → **+ Add Alias**:

    | Поле | Значение |
    |------|----------|
    | Name | `russian-ips` |
    | Type | Network (ipset) |

    **Save**.

21. Нажать кнопку **Generate** рядом с `russian-ips`:
    - Source: **RIPE**
    - Country: **RU**
    - **Generate**

    Подождать 1–3 минуты — загрузится ~6 000 российских сетей.

### 4.4. Правила маршрутизации (PBR)

22. **Firewall** → **Rules** → **+ Add Rule** — *Правило 1: российский трафик через RF*:

    | Поле | Значение |
    |------|----------|
    | Source | `10.0.0.0/24` |
    | Destination | `russian-ips` *(выбрать из списка)* |
    | Action | ACCEPT |
    | Gateway | *(пусто — маршрут по умолчанию)* |

    **Save**.

23. **+ Add Rule** — *Правило 2: остальной трафик через NL*:

    | Поле | Значение |
    |------|----------|
    | Source | `10.0.0.0/24` |
    | Destination | `any` |
    | Action | ACCEPT |
    | Gateway | `netherlands` |

    **Save**.

    > ⚠️ **Важно:** Правило 1 должно стоять **выше** Правила 2 в списке.
    > Перетащить стрелками ↑↓ если нужно.

---

## Часть 5. Добавить первого клиента

24. **Interfaces** → `wg0` → **Add Peer**:

    | Поле | Значение |
    |------|----------|
    | Name | `мой-телефон` *(любое)* |
    | Type | Client |
    | Allowed IPs | `0.0.0.0/0` *(весь трафик через VPN)* |

    **Save**.

25. Нажать **QR** → отсканировать в приложении **AmneziaWG** *(не стандартный WireGuard)*.

    > Если использовали WireGuard 1.0 — подойдёт стандартное приложение WireGuard.

## Проверка

После подключения клиента к VPN открыть в браузере:

| Сайт | Что покажет |
|------|-------------|
| [2ip.ru](https://2ip.ru) | IP RF-сервера *(российский ресурс → RF выход)* |
| [whatismyip.com](https://whatismyip.com) | IP NL-сервера *(зарубежный ресурс → NL выход)* |

## Устранение проблем

| Симптом | Что проверить |
|---------|--------------|
| Нет интернета вообще | NAT на RF (шаг 10), Default Policy в Firewall |
| Весь трафик идёт через NL | Правило 1 стоит выше Правила 2? Алиас `russian-ips` сгенерирован? |
| Весь трафик через RF | Gateway `netherlands` Online? Правило 2 с Gateway сохранено? |
| Туннель не поднимается | Порт `51821` открыт на обоих серверах? Проверить Handshake в Interfaces |
| Remotes: Test → Error | URL правильный? TLS сертификат валидный? Попробовать **Skip TLS verify** |
| Gateway Offline | Ping target `1.1.1.1` доступен с NL? Проверить NAT на NL (шаг 13) |
